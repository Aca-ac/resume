# 简历分析模块接口设计

## 1. 概述

本模块提供简历与职位描述（JD）的匹配分析接口，包含匹配计算、历史记录查询和分析详情查询三大功能，支持雷达图多维度评分展示。

## 2. 接口清单

| 接口路径 | HTTP方法 | 所属Controller | 功能描述 |
| :--- | :--- | :--- | :--- |
| `/api/v1/match/jd` | POST | MatchController | 执行简历与JD的匹配分析 |
| `/api/v1/match/history` | GET | MatchController | 查询用户的匹配历史记录 |
| `/api/v1/match/analysis/{id}` | GET | MatchController | 查询匹配分析详情（含维度评分） |

## 3. 接口详细设计

### 3.1 POST /api/v1/match/jd

**功能描述**: 执行简历与职位描述（JD）的匹配分析，调用AI模型进行智能评分，返回匹配结果及各维度评分数据。

**请求参数**:
- userId: Long (RequestAttribute) - 当前登录用户ID（由网关注入）
- body: MatchJdRequest (RequestBody) - 匹配请求体

**限流配置**: @RateLimiter(key = "match", maxCount = 20, duration = 60)

**响应**: Result\<MatchRecordVO\>

#### 3.1.1 请求体结构

| 字段名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| resumeId | Long | 是 | 简历ID |
| jdText | String | 是 | 职位描述原文 |

#### 3.1.2 响应结构

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | Long | 匹配记录ID |
| resumeId | Long | 简历ID |
| matchScore | Integer | 匹配总分 0-100 |
| summaryScore | Integer | 个人总结评分 0-100 |
| educationScore | Integer | 教育背景评分 0-100 |
| experienceScore | Integer | 工作经历评分 0-100 |
| skillScore | Integer | 专业技能评分 0-100 |
| projectScore | Integer | 项目经历评分 0-100 |
| analysisId | Long | 关联分析记录ID |
| analysis | String | 匹配分析说明 |
| createdAt | String | 创建时间 |

#### 3.1.3 业务流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        POST /api/v1/match/jd 业务流程                        │
├─────────────────────────────────────────────────────────────────────────────┤
│  1. 参数校验层                                                              │
│     ├─ resumeId 不能为空                                                    │
│     ├─ jdText 不能为空且非空白                                               │
│     └─ 校验失败返回 400 错误                                                 │
│                              ↓                                              │
│  2. 简历权限验证                                                             │
│     ├─ 根据 resumeId 查询 Resume 记录                                        │
│     ├─ 验证 Resume 存在且属于当前用户(userId)                                 │
│     └─ 验证失败返回 404 错误                                                 │
│                              ↓                                              │
│  3. 简历内容构建                                                             │
│     ├─ 查询 ResumeDetail 表获取简历各章节内容                                │
│     ├─ 按 sort_order 排序拼接完整简历文本                                    │
│     └─ 内容为空返回 400 错误                                                 │
│                              ↓                                              │
│  4. AI配置检查                                                              │
│     ├─ 检查 DASHSCOPE_API_KEY 是否已配置                                     │
│     └─ 未配置返回 500 错误                                                  │
│                              ↓                                              │
│  5. 调用AI模型分析                                                           │
│     ├─ 加载提示词模板 prompts/resume_analysis_prompt.txt                     │
│     ├─ 拼接简历内容和JD文本构建完整Prompt                                     │
│     ├─ 调用阿里云通义千问API (qwen-plus)                                     │
│     └─ 解析返回的JSON结果                                                    │
│                              ↓                                              │
│  6. 维度评分计算                                                             │
│     ├─ 根据配置的维度预设(general/technical/management)构建维度列表           │
│     ├─ 从AI结果中提取各维度分数并限制在0-100范围                              │
│     ├─ 计算雷达图加权总分                                                   │
│     ├─ 推导匹配等级(excellent/good/average/poor)                            │
│     ├─ 提取或推导亮点(≥75分维度)                                            │
│     └─ 提取或推导待提升点(<60分维度)                                         │
│                              ↓                                              │
│  7. 数据持久化（事务）                                                        │
│     ├─ 插入 match_analysis 主表记录                                          │
│     ├─ 插入 match_dimension 维度评分记录                                     │
│     ├─ 插入 match_sub_dimension 子维度记录（如有）                            │
│     ├─ 插入 match_records 匹配记录                                           │
│     └─ 建立 analysis_id 关联                                                │
│                              ↓                                              │
│  8. 返回结果                                                                 │
│     └─ 转换为 MatchRecordVO 返回                                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 3.1.4 详细业务步骤

**步骤1-4：前置校验**
- 参数校验：确保 resumeId 和 jdText 不为空
- 权限验证：确保简历属于当前用户
- 内容构建：从 ResumeDetail 表按顺序拼接简历各章节
- 配置检查：确保 AI API Key 已配置

**步骤5：AI调用流程**
- 加载提示词模板：从 classpath:prompts/resume_analysis_prompt.txt 读取
- Prompt构建：将简历内容替换模板中的占位符，追加JD文本
- API调用：POST 请求到阿里云通义千问 API
  - URL: `${baseUrl}/chat/completions`
  - 模型: qwen-plus（可配置）
  - Headers: Bearer Auth + JSON Content-Type
- 结果解析：提取 choices[0].message.content

**步骤6：维度计算流程**
- 预设维度：
  - general（通用）：个人总结、教育背景、工作经历、专业技能、项目经历
  - technical（技术）：强调技术能力维度
  - management（管理）：强调管理能力维度
- 分数归一化：所有分数限制在 0-100 范围
- 加权总分：`Σ(dimension_score * dimension_weight) / Σ(dimension_weight)`
- 等级映射：
  - ≥85 → excellent（优秀）
  - 70-84 → good（良好）
  - 50-69 → average（一般）
  - <50 → poor（较差）
- 亮点推导：维度分数 ≥75 分自动生成亮点描述
- 弱点推导：维度分数 <60 分自动生成待提升描述

**步骤7：持久化流程**
- 开启事务 @Transactional
- 先插入 match_analysis 获取分析ID
- 批量插入 match_dimension 维度记录
- 批量插入 match_sub_dimension 子维度记录
- 插入 match_records 并关联 analysis_id

### 3.2 GET /api/v1/match/history

**功能描述**: 分页查询当前用户的历史匹配记录列表。

**请求参数**:
- userId: Long (RequestAttribute) - 当前登录用户ID（由网关注入）
- page: int (RequestParam, 默认值"1") - 页码（最小1）
- size: int (RequestParam, 默认值"50") - 每页条数（1-100）

**响应**: Result\<PageResult\<MatchRecordVO\>\>

#### 3.2.1 响应结构

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| records | List\<MatchRecordVO\> | 匹配记录列表 |
| total | long | 总记录数 |
| page | long | 当前页码 |
| size | long | 每页条数 |

#### 3.2.2 业务流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      GET /api/v1/match/history 业务流程                     │
├─────────────────────────────────────────────────────────────────────────────┤
│  1. 参数校验                                                                 │
│     ├─ page < 1 → 修正为 1                                                  │
│     └─ size < 1 或 size > 100 → 修正为 50                                   │
│                              ↓                                              │
│  2. 分页查询                                                                 │
│     ├─ 使用 MyBatis-Plus 分页插件                                           │
│     ├─ 构建查询条件: userId = 当前用户ID                                     │
│     └─ 排序: created_at DESC（按创建时间降序）                                │
│                              ↓                                              │
│  3. 结果转换                                                                 │
│     ├─ 将 MatchRecord 实体列表转换为 MatchRecordVO                            │
│     └─ 包装为 PageResult 返回                                               │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 GET /api/v1/match/analysis/{id}

**功能描述**: 查询匹配分析详情，包含完整的维度评分、亮点、待提升点和建议信息，用于雷达图展示。

**请求参数**:
- userId: Long (RequestAttribute) - 当前登录用户ID（由网关注入）
- id: Long (PathVariable) - 分析记录ID（match_analysis.id）

**响应**: Result\<MatchAnalysisResultVO\>

#### 3.3.1 响应结构

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | Long | 分析记录ID |
| resumeId | Long | 简历ID |
| jobDescriptionId | Long | 职位描述ID（预留） |
| matchScore | Integer | 匹配总分 0-100 |
| matchLevel | String | 匹配等级：excellent/good/average/poor |
| dimensions | List\<DimensionScoreVO\> | 维度评分列表 |
| analysis | String | 详细分析文本 |
| summary | String | 简短总结（最多500字符） |
| highlights | List\<String\> | 亮点数组 |
| weaknesses | List\<String\> | 待提升点数组 |
| suggestions | List\<SuggestionVO\> | 建议数组 |
| createdAt | String | 创建时间 |
| updatedAt | String | 更新时间 |
| version | String | 版本号 |

#### 3.3.2 DimensionScoreVO 结构

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | Long | 维度ID |
| name | String | 维度名称 |
| score | Integer | 维度评分 0-100 |
| weight | BigDecimal | 权重系数 |
| description | String | 维度说明 |
| details | String | 详细说明 |
| subDimensions | List\<SubDimensionVO\> | 子维度列表 |

#### 3.3.3 SuggestionVO 结构

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| type | String | 类型：improve（改进建议）等 |
| title | String | 建议标题 |
| description | String | 建议描述 |
| priority | String | 优先级：high/medium/low |
| category | String | 分类：general等 |

#### 3.3.4 SubDimensionVO 结构

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| name | String | 子维度名称 |
| score | Integer | 子维度评分 0-100 |
| description | String | 子维度说明 |

#### 3.3.5 业务流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                   GET /api/v1/match/analysis/{id} 业务流程                   │
├─────────────────────────────────────────────────────────────────────────────┤
│  1. 查询分析主记录                                                           │
│     ├─ 根据 id 查询 match_analysis 表                                       │
│     ├─ 验证记录存在且属于当前用户(userId)                                    │
│     └─ 验证失败返回 404 错误                                                 │
│                              ↓                                              │
│  2. 查询维度列表                                                             │
│     ├─ 根据 analysis_id 查询 match_dimension 表                             │
│     └─ 按 sort_order 升序排列                                               │
│                              ↓                                              │
│  3. 查询子维度列表                                                           │
│     ├─ 遍历每个维度，根据 dimension_id 查询 match_sub_dimension 表           │
│     └─ 按 sort_order 升序排列                                               │
│                              ↓                                              │
│  4. JSON字段解析                                                             │
│     ├─ highlights JSON → List<String>                                       │
│     ├─ weaknesses JSON → List<String>                                       │
│     └─ suggestions JSON → List<SuggestionVO>                                │
│                              ↓                                              │
│  5. 结果组装                                                                 │
│     └─ 转换为 MatchAnalysisResultVO 返回                                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 5. 错误码定义

| 错误码 | 错误信息 | 触发条件 |
| :--- | :--- | :--- |
| 400 | 请选择简历 | resumeId 为空 |
| 400 | 请粘贴职位描述 | jdText 为空或空白 |
| 400 | 简历内容为空，请先完善简历 | ResumeDetail 无内容 |
| 404 | 简历不存在 | 简历不存在或不属于当前用户 |
| 404 | 分析记录不存在 | 分析记录不存在或不属于当前用户 |
| 500 | 未配置 DASHSCOPE_API_KEY，无法进行匹配分析 | AI API Key 未配置 |
| 500 | 提示词文件不存在 | prompts/resume_analysis_prompt.txt 不存在 |
| 500 | AI 未返回有效内容 | AI API 返回空内容 |
| 500 | 匹配分析服务异常：{status} | AI API 调用失败 |
| 500 | 匹配分析失败：{message} | 其他系统异常 |

## 6. 数据库表关联关系

```
users ──1:N── match_records ──1:1── match_analysis
                    │                      │
                    │                      │
                    └──1:N── match_dimension ──1:N── match_sub_dimension
```

**说明**:
- match_records 与 match_analysis 为一对一关联（通过 analysis_id）
- match_analysis 与 match_dimension 为一对多关联（通过 analysis_id）
- match_dimension 与 match_sub_dimension 为一对多关联（通过 dimension_id）
- 所有外键均采用 CASCADE 删除策略，确保数据一致性
