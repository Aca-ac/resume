# 岗位匹配推荐模块业务流程

## 1. 模块概述

岗位匹配推荐模块基于用户简历内容进行岗位推荐，支持两种数据源：
- **路径A（联网搜索）**：调用豆包AI联网搜索获取外部岗位信息
- **路径B（平台内匹配）**：基于语义向量余弦值计算筛选平台内匹配岗位

最终整合两条路径的结果返回给用户，无匹配结果时调用千问模型给出简历改进建议。

## 2. 岗位推荐主流程

用户请求 (POST /api/v1/match/recommend)
→ 参数校验（resumeId、userId非空，限流5次/60秒）
→ 简历权限验证（查询Resume，验证存在且属于当前用户，验证内容非空）
→ 构建简历内容（查询ResumeDetail，按sortOrder拼接）
→ 判断 enableWebSearch：
  ├─ true → 并行执行路径A和路径B
  └─ false → 仅执行路径B
→ 结果整合（合并两条路径结果 → 按匹配度降序排序 → 过滤匹配度<30分）
→ 判断结果是否为空：
  ├─ 不为空 → 保存推荐记录 → 返回推荐结果
  └─ 为空 → 判断 enableWebSearch：
       ├─ true → 调用千问模型生成简历改进建议
       └─ false → 返回平台内无岗位提示（建议开启联网搜索）
→ 保存会话记录 → 返回推荐结果

## 3. 路径A：联网搜索流程

输入：userId + resumeId
→ 权限验证与内容构建（查询Resume验证归属，拼接ResumeDetail内容）
→ 检查API Key配置（未配置则返回空列表）
→ 构建搜索Prompt（加载模板，替换{resume_content}）
→ 调用豆包AI联网搜索接口（端点：/responses，工具：web_search）
→ 解析搜索结果（提取JSON数组，计算5维度加权总分，生成matchReason）
→ 结果筛选（过滤匹配度<30分，去除来源链接和岗位名称为空的结果）
→ 岗位持久化副作用（检查sourceUrl是否存在，不存在则插入target_job表，source=1）
→ 输出：List<JobRecommendationVO>（source="NETWORK"）

## 4. 路径B：平台内匹配流程

输入：userId + resumeId
→ 权限验证与内容构建（查询Resume验证归属，拼接ResumeDetail内容）
→ 获取平台内所有岗位（查询target_job表）
→ 获取/生成简历向量（查询缓存 → 有缓存且未修改则读取，否则生成并写入缓存）
→ 批量检查岗位JD向量缓存（分离有缓存/需生成）
→ 并行生成缺失/过期岗位向量（CompletableFuture并行，间隔1.1秒，写入缓存）
→ 计算余弦相似度（简历向量与各岗位向量）
→ 筛选Top 2匹配岗位（按余弦相似度降序）
→ AI评分验证（构建Prompt，调用千问模型给出5维度评分）
→ 降级机制（AI评分失败时，使用cosine_similarity * 100作为分数）
→ 低分过滤（匹配度<30分的岗位删除）
→ 输出：List<JobRecommendationVO>（source="PLATFORM"）

## 5. 结果整合流程

输入：路径A结果 + 路径B结果
→ 合并结果（保留来源标记NETWORK/PLATFORM）
→ 按匹配度降序排序
→ 过滤匹配度<30分的岗位
→ 输出：整合后的最终推荐列表

## 6. 无匹配结果处理流程

触发条件：路径A和路径B均返回空列表
→ 判断 enableWebSearch：
  ├─ false → 直接生成平台内无结果建议（priority=medium）
  └─ true → 检查千问API Key：
       ├─ 未配置 → 返回null（无改进建议）
       └─ 已配置 → 构建改进建议Prompt → 调用千问模型生成建议 → 解析建议结果（问题描述、改进建议列表、优先级）
→ 输出：ImprovementSuggestionVO（或null）

## 7. 评分机制

两条路径均采用统一的5维度加权评分：
- summary_score（10%）：个人总结匹配度
- education_score（15%）：教育背景匹配度
- experience_score（25%）：工作经历匹配度
- skill_score（25%）：专业技能匹配度
- project_score（25%）：项目经历匹配度

综合评分公式：总分 = summary × 0.10 + education × 0.15 + experience × 0.25 + skill × 0.25 + project × 0.25

阈值规则：匹配度低于30分的岗位直接过滤，不返回给用户。

## 8. 核心优化策略

- **向量缓存机制**：简历向量、岗位JD向量存入专用向量表，支持modified_flag标记判断是否需要重新生成
- **并行执行**：路径A与路径B使用CompletableFuture并行执行，提高性能
- **并行向量生成**：岗位向量使用CompletableFuture并行生成，每个请求间隔1.1秒避免API限流
