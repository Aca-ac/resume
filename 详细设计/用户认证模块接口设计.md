# 用户认证模块接口设计

## 1. 模块概述

用户认证模块负责处理用户的注册、登录、Token刷新和个人信息管理等核心功能。基于Spring Security + JWT实现认证鉴权，采用邮箱+验证码的方式完成注册。

## 2. 接口列表

### 2.1 发送邮箱验证码

| 项目   | 内容                       |
|------|--------------------------|
| 接口路径 | `/api/v1/auth/code/send` |
| 请求方式 | POST                     |
| 功能说明 | 用户输入邮箱后，系统发送6位数字验证码至该邮箱  |

**请求参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| email | String | 是 | 用户邮箱地址 |

**响应示例：**

{"code": 200, "message": "验证码已发送", "data": {"expireSeconds": 300}}

**业务规则：**
- 验证码有效期：5分钟
- 同一邮箱60秒内只能发送一次
- 验证码为6位纯数字

---

### 2.2 用户注册

| 项目 | 内容 |
|------|------|
| 接口路径 | `/api/v1/auth/register` |
| 请求方式 | POST |
| 功能说明 | 用户通过邮箱+密码+验证码完成注册 |

**请求参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| email | String | 是 | 用户邮箱 |
| password | String | 是 | 密码（6-20位，需包含字母和数字） |
| code | String | 是 | 邮箱验证码（6位数字） |

**响应示例：**

{"code": 200, "message": "注册成功", "data": {"accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "expiresInSeconds": 300, "userId": 10001}}


---

### 2.3 用户登录

| 项目 | 内容 |
|------|------|
| 接口路径 | `/api/v1/auth/login` |
| 请求方式 | POST |
| 功能说明 | 用户通过邮箱+密码登录，获取Token |

**请求参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| email | String | 是 | 用户邮箱 |
| password | String | 是 | 登录密码 |

**响应示例：**

{"code": 200, "message": "登录成功", "data": {"accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "expiresIn": 7200, "userId": 10001}}

**业务规则：**
- 密码错误返回"邮箱或密码错误"
- 账号禁用返回"账号已被禁用"

---

### 2.4 刷新Token

| 项目 | 内容 |
|------|------|
| 接口路径 | `/api/v1/auth/refresh` |
| 请求方式 | POST |
| 功能说明 | 使用旧的快过期的JWT Token生成新的JWT Token |

**响应示例：**

{"code": 200, "message": "刷新成功", "data": {"accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "expiresIn": 7200}}

**业务规则：**
- 旧Token只需满足：未完全过期（允许宽限期，如过期5分钟内仍可刷新）
- 新Token有效期从当前时间重新计算

---

### 2.5 获取个人信息

| 项目 | 内容 |
|------|------|
| 接口路径 | `/api/v1/user/profile` |
| 请求方式 | GET |

### 2.6 更新个人信息

| 项目 | 内容 |
|------|------|
| 接口路径 | `/api/v1/user/profile` |
| 请求方式 | PUT |
| 功能说明 | 更新当前登录用户的个人信息 |

| 参数名 | 类型 | 必填 | 说明 |

**响应示例：**

### 2.7 忘记密码

| 项目 | 内容 |
|------|------|
| 接口路径 | `/api/v1/auth/password/reset` |
| 请求方式 | POST |
| 功能说明 | 用户通过验证码重置密码 |

**请求参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| email | String | 是 | 用户邮箱 |
| password | String | 是 | 新密码（6-20位，需包含字母和数字） |
| code | String | 是 | 邮箱验证码（6位数字） |

**响应示例：**

{"code": 200, "message": "密码重置成功", "data": null}

**业务规则：**
- 验证码错误返回"验证码错误"
- 验证码过期返回"验证码已过期"
- 邮箱未注册返回"邮箱未注册"

---

## 3. Token设计

### Access Token

- 格式：JWT
- 有效期：2小时
- 包含信息：userId、email、nickname、issuedAt、expiredAt
- 刷新机制：使用快过期的旧Token（允许过期5分钟宽限期）直接生成新Token，无需数据库存储

---

## 4. 错误码定义

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | Token无效或已过期（无法刷新） |
| 403 | 账号已被禁用 |
| 429 | 请求过于频繁 |
| 500 | 服务器内部错误 |

| 业务错误码 | 说明 |
|------------|------|
| AUTH_001 | 邮箱格式错误 |
| AUTH_002 | 密码格式错误 |
| AUTH_003 | 验证码错误 |
| AUTH_004 | 验证码已过期 |
| AUTH_005 | 邮箱已被注册 |
| AUTH_006 | 邮箱或密码错误 |
| AUTH_007 | 账号已被禁用 |
| AUTH_008 | Token已过期，无法刷新 |
| AUTH_009 | 验证码发送过于频繁 |
