# 岗位修改/简历修改接口变更设计

## 变更目的
支持岗位匹配推荐模块的向量缓存机制，当岗位内容（JD）或简历内容被修改时，更新对应语义向量表的 `modified_flag` 标记位，确保下次匹配时重新生成向量。

## 变更范围
| 模块 | 变更内容 |
|------|----------|
| **岗位** | `JobService.updateJob` 增加向量缓存失效处理，新增 `JobSemanticVectorMapper` 更新操作 |
| **简历** | `ResumeService.updateResume` 增加向量缓存失效处理，新增 `ResumeSemanticVectorMapper` 更新操作 |

## 核心变更逻辑

### 岗位修改接口 (`PUT /api/v1/jobs/{id}`)
- **变更前**：直接更新 `target_jobs` 表
- **变更后**：
  1. 判断 `jdContent` 是否变更
  2. 若变更，更新 `job_semantic_vector` 表对应记录的 `modified_flag = 1`
  3. 若向量记录不存在，不报错（下次匹配时自动创建）

### 简历修改接口 (`PUT /api/v1/resumes/{id}`)
- **变更前**：直接更新 `resumes` 表
- **变更后**：
  1. 判断内容是否变更
  2. 若变更，更新 `resume_semantic_vector` 表对应记录的 `modified_flag = 1`
  3. 若向量记录不存在，不报错（下次匹配时自动创建）

## 变更原则
| 原则 | 说明 |
|------|------|
| 最小侵入 | 仅在内容修改时触发向量缓存失效，标题修改不影响 |
| 事务一致性 | 数据更新和向量标记更新在同一事务中完成 |
| 幂等性 | 向量表中无对应记录时不报错 |

## 数据库约束
- 岗位语义向量表与岗位表通过外键关联，支持 `ON DELETE CASCADE`
- 简历语义向量表与简历表通过外键关联，支持 `ON DELETE CASCADE`

## 变更影响
| 影响项 | 评估 |
|--------|------|
| API兼容性 | 无影响，接口路径、请求体、响应体均不变 |
| 性能 | 增加一次条件查询和可能的更新，影响可忽略 |
| 向后兼容 | 完全兼容 |

## 测试要点
| 场景 | 预期结果 |
|------|----------|
| 修改标题（不修改内容） | `modified_flag` 保持为 0 |
| 修改内容 | `modified_flag` 更新为 1 |
| 修改内容为相同值 | 向量缓存不失效 |
| 修改不存在的资源 | 返回 404 |
| 修改他人资源 | 返回 403 |
| 删除资源 | 语义向量记录被级联删除 |
| 新创建后修改内容 | 向量记录不存在，不报错 |

## 核心要点总结
本次变更为无感知升级，API 对外保持不变，仅在内部增加了向量缓存失效机制——当 JD/简历内容实际变更时，通过标记 `modified_flag = 1` 通知匹配模块重新生成向量，确保推荐结果的准确性。
