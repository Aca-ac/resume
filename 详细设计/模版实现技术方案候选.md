# 简历模板实现技术方案候选

> **版本**：V1（2026-07）  
> **依据**：`功能设计/sprint2.md` 中「简历模板与模板化导出模块」需求  
> **项目技术栈**：Spring Boot 3 · Vue 3 · Apache POI 5.2.5 · PDFBox 3.0.3 · Element Plus


---

## 一、需求分析

根据 `sprint2.md` 第 2.1 小节「简历模板与模板化导出模块」（对应架构文档 4.1.3、4.1.9、4.2.7、4.2.8），模板模块需要实现以下核心功能：

| 序号 | 需求点 | 描述 |
|------|--------|------|
| 1 | 模板信息表设计 | 字段：id、name、category、preview_url、template_path、applicable_scene、created_at、updated_at |
| 2 | 模板 CRUD 接口 | 模板的新增、列表、详情、删除 |
| 3 | 模板智能推荐算法 | 根据用户工作年限、行业、目标岗位推荐适配模板 |
| 4 | 模板渲染方案 | 占位符替换、样式控制、分段内容嵌入 |
| 5 | 简历导出为 Word | 基于模板渲染，自动填充个人信息与简历分段 |
| 6 | 简历导出为 PDF | 模板渲染 + PDF 转换 |
| 7 | 导出文件临时存储与下载 | 导出文件的临时存储与下载接口 |

**关键约束**：
- 模板只优化样式和排版，不改变简历内容
- 需支持分段内容（教育、工作、项目、技能、SUMMARY）的嵌入
- 导出文件需排版整洁、无乱码，样式正确渲染，符合正式投递标准
- 难度需符合大学生课程设计水平
- 技术选型待定：模板渲染引擎（poi-tl / Freemarker / Thymeleaf）、PDF 转换方案需评审确定

## 二、候选方案一：前端 CSS 模板 + 浏览器打印导出

### 2.1 实现思路

利用前端 CSS 能力实现模板样式，通过浏览器原生打印功能或 `html2canvas` 库将渲染好的 HTML 转换为图片/PDF。

**核心流程**：
```
用户选择模板 → 前端加载对应 CSS 样式 → 渲染简历预览 → 用户点击导出 → 浏览器打印/截图 → 下载
```

### 2.2 技术依赖

| 依赖 | 用途 | 是否已引入 |
|------|------|------------|
| Vue 3 | 前端框架 | ✅ 已引入 |
| Element Plus | UI 组件库 | ✅ 已引入 |
| html2canvas | HTML 转 Canvas | ❌ 需新增 |
| jspdf | Canvas 转 PDF | ❌ 需新增 |

### 2.3 实现步骤

**后端部分**：
1. 设计 `resume_templates` 表，存储模板名称、分类、预览图 URL
2. 实现模板 CRUD 接口
3. 实现模板推荐接口（根据用户信息返回推荐模板列表）

**前端部分**：
1. 创建模板广场页面，展示所有模板
2. 创建模板预览页面，根据选中模板加载对应 CSS
3. 将简历分段数据（教育、工作、项目、技能）渲染为结构化 HTML
4. 使用 `html2canvas` 将渲染好的简历区域截图
5. 使用 `jspdf` 将截图转换为 PDF 文件下载
6. Word 导出：将 HTML 保存为 `.doc` 文件（浏览器原生支持）

### 2.4 模板数据结构

```sql
CREATE TABLE resume_templates (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(64) NOT NULL COMMENT '模板名称',
    category VARCHAR(32) NOT NULL COMMENT '分类（如：简约、专业、创意）',
    preview_url VARCHAR(512) COMMENT '预览图路径',
    style_class VARCHAR(64) NOT NULL COMMENT 'CSS 样式类名',
    applicable_scene VARCHAR(128) COMMENT '适用场景（如：应届生、互联网、金融）',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME ON UPDATE CURRENT_TIMESTAMP
);
```

### 2.5 优缺点

**优点**：
- 实现最简单，前端开发者熟悉
- 无需后端复杂处理，响应速度快
- 模板样式调试直观，所见即所得
- 无需额外后端依赖

**缺点**：
- PDF 质量依赖浏览器渲染，不同浏览器可能有差异
- Word 导出格式受限（实际是 HTML 伪装成 .doc）
- 无法精确控制分页、页眉页脚等专业排版
- 打印时可能出现背景丢失、字体不一致等问题

## 三、候选方案二：后端 poi-tl 基于 .docx 模板文件

> **对应 sprint2.md 指定的技术选型**：poi-tl 模板渲染引擎

### 3.1 实现思路

使用 poi-tl（poi template language）作为 Word 模板引擎，基于 Apache POI 实现 `.docx` 模板文件的占位符替换和内容填充。poi-tl 提供声明式模板语法，无需手写 POI 替换逻辑。

**核心流程**：
```
用户选择模板 → 前端请求导出 → 后端读取 .docx 模板 → poi-tl 替换占位符 → 生成新文档 → 返回下载
```

### 3.2 技术依赖

| 依赖 | 用途 | 是否已引入 |
|------|------|------------|
| Apache POI 5.2.5 | Word 文档处理基础 | ✅ 已引入 |
| poi-tl 1.12.0+ | Word 模板引擎（基于 POI） | ❌ 需新增 |
| PDFBox 3.0.3 | PDF 生成 | ✅ 已引入 |

**pom.xml 新增依赖**：
```xml
<dependency>
    <groupId>com.deepoove</groupId>
    <artifactId>poi-tl</artifactId>
    <version>1.12.0</version>
</dependency>
```

> **兼容性说明**：poi-tl 1.12.0 依赖 Apache POI 5.2.2+，项目当前使用 POI 5.2.5，完全兼容。

### 3.3 实现步骤

**模板准备**：
1. 在 `src/main/resources/templates/resumes/` 目录下放置多个 `.docx` 模板文件
2. 模板中使用 poi-tl 占位符语法，如 `{{name}}`、`{{education}}` 等

**后端实现**：
1. 设计 `resume_templates` 表，存储模板元数据和模板文件路径
2. 实现模板 CRUD 接口
3. 实现模板推荐接口
4. 创建 `TemplateRenderService`，使用 poi-tl 的 `XWPFTemplate.compile()` 编译模板，`render()` 填充数据
5. 创建 `ResumeExportService`，集成模板渲染和文件导出
6. PDF 导出：先生成 Word，再通过外部工具转换为 PDF（详见 3.6）

**前端实现**：
1. 模板广场页面展示模板列表和预览
2. 导出页面选择模板和导出格式
3. 调用导出接口，接收二进制文件流下载

### 3.4 模板文件格式示例

使用 poi-tl 的 `{{}}` 占位符语法：

```
简历模板.docx 内容结构：
├── 标题：{{title}}
├── 基本信息：
│   ├── 姓名：{{name}}
│   ├── 电话：{{phone}}
│   └── 邮箱：{{email}}
├── 教育经历：{{education}}
├── 工作经历：{{workExperience}}
├── 项目经验：{{project}}
└── 技能：{{skill}}
```

### 3.5 核心代码示例

```java
@Service
public class TemplateRenderService {
    
    public byte[] renderWord(Long templateId, ResumeData data) throws IOException {
        ResumeTemplate template = templateMapper.selectById(templateId);
        
        InputStream templateStream = getClass().getResourceAsStream(template.getTemplatePath());
        XWPFTemplate xwpfTemplate = XWPFTemplate.compile(templateStream);
        
        Map<String, Object> dataMap = new HashMap<>();
        dataMap.put("title", data.getTitle());
        dataMap.put("name", data.getName());
        dataMap.put("phone", data.getPhone());
        dataMap.put("email", data.getEmail());
        dataMap.put("education", data.getEducation());
        dataMap.put("workExperience", data.getWorkExperience());
        dataMap.put("project", data.getProject());
        dataMap.put("skill", data.getSkill());
        dataMap.put("summary", data.getSummary());
        
        xwpfTemplate.render(dataMap);
        
        ByteArrayOutputStream out = new ByteArrayOutputStream();
        xwpfTemplate.write(out);
        xwpfTemplate.close();
        
        return out.toByteArray();
    }
}
```

### 3.6 PDF 导出方案

由于 poi-tl 仅支持 Word 生成，PDF 导出需要额外处理：

**方案 A（推荐）**：使用 LibreOffice 命令行转换
```bash
libreoffice --headless --convert-to pdf --outdir /tmp output.docx
```

**方案 B**：使用 docx4j 进行转换（需新增依赖）

**方案 C**：使用 PDFBox 直接渲染文本（样式与 Word 模板不一致）

### 3.7 优缺点

**优点**：
- 模板语法简单直观（`{{name}}` 风格）
- Word 导出质量高，保留模板样式（字体、颜色、排版）
- 模板文件可使用 Word 软件直接编辑，方便维护
- 相比手写 POI 替换，代码量大幅减少
- 基于项目已有 POI 依赖，学习成本低

**缺点**：
- PDF 导出需要外部工具或额外依赖，样式一致性难以保证
- 模板文件需预先制作，灵活性较低
- 动态内容长度可能导致排版错乱（如分页问题）

## 四、候选方案三：后端 Thymeleaf/Freemarker 模板渲染 + PDF 转换

> **对应 sprint2.md 指定的技术选型**：Thymeleaf / Freemarker 模板渲染引擎

### 4.1 实现思路

使用服务器端模板引擎（Thymeleaf 或 Freemarker）渲染 HTML 模板，再通过 HTML 转 PDF 工具（如 OpenPDF/Flying Saucer）生成 PDF 文件。Word 导出通过渲染 HTML 后让浏览器保存为 `.doc` 格式。

**核心流程**：
```
用户选择模板 → 请求导出 → 后端读取 HTML 模板 → 模板引擎渲染 → HTML转PDF/Word → 返回下载
```

### 4.2 技术依赖

| 依赖 | 用途 | 是否已引入 |
|------|------|------------|
| Thymeleaf | HTML 模板引擎（推荐） | ❌ 需新增 |
| OpenPDF/Flying Saucer | HTML 转 PDF | ❌ 需新增 |
| Apache POI | Word 生成（可选） | ✅ 已引入 |

**pom.xml 新增依赖**：
```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-thymeleaf</artifactId>
</dependency>
<dependency>
    <groupId>org.xhtmlrenderer</groupId>
    <artifactId>flying-saucer-pdf</artifactId>
    <version>9.1.22</version>
</dependency>
```

### 4.3 实现步骤

**模板准备**：
1. 在 `src/main/resources/templates/resumes/` 目录下放置 HTML 模板文件
2. 使用 Thymeleaf 语法编写模板，支持循环、条件判断、变量替换等

**后端实现**：
1. 添加 Thymeleaf 和 Flying Saucer 依赖
2. 设计 `resume_templates` 表，存储模板元数据和 HTML 模板路径
3. 实现模板 CRUD 和推荐接口
4. 创建 `TemplateRenderService`，使用 Thymeleaf 渲染 HTML
5. 创建 PDF 转换服务，使用 Flying Saucer 将 HTML 转为 PDF
6. Word 导出：渲染 HTML 后直接返回，浏览器保存为 `.doc`

**前端实现**：
1. 模板广场页面展示模板列表
2. 实时预览使用后端渲染的 HTML
3. 导出页面选择模板和格式，调用导出接口

### 4.4 HTML 模板示例

使用 Thymeleaf 语法：

```html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <style>
        @page { size: A4; margin: 2cm; }
        .resume-title { font-size: 24px; font-weight: bold; text-align: center; margin-bottom: 20px; }
        .section-title { font-size: 16px; font-weight: bold; margin-top: 16px; color: #333; }
        .content { font-size: 14px; line-height: 1.8; color: #666; }
        .basic-info { display: flex; justify-content: center; gap: 30px; }
    </style>
</head>
<body>
    <div class="resume-title" th:text="${title}"></div>
    
    <div class="basic-info">
        <span>姓名：<span th:text="${name}"></span></span>
        <span>电话：<span th:text="${phone}"></span></span>
        <span>邮箱：<span th:text="${email}"></span></span>
    </div>
    
    <div class="section-title">教育经历</div>
    <div class="content" th:text="${education}"></div>
    
    <div class="section-title">工作经历</div>
    <div class="content" th:text="${workExperience}"></div>
    
    <div class="section-title">项目经验</div>
    <div class="content" th:text="${project}"></div>
    
    <div class="section-title">技能</div>
    <div class="content" th:text="${skill}"></div>
    
    <div class="section-title">个人简介</div>
    <div class="content" th:text="${summary}"></div>
</body>
</html>
```

### 4.5 核心代码示例

```java
@Service
public class TemplateRenderService {
    
    @Autowired
    private TemplateEngine templateEngine;
    
    public byte[] renderPdf(Long templateId, ResumeData data) throws IOException {
        ResumeTemplate template = templateMapper.selectById(templateId);
        
        Context context = new Context();
        context.setVariable("title", data.getTitle());
        context.setVariable("name", data.getName());
        context.setVariable("phone", data.getPhone());
        context.setVariable("email", data.getEmail());
        context.setVariable("education", data.getEducation());
        context.setVariable("workExperience", data.getWorkExperience());
        context.setVariable("project", data.getProject());
        context.setVariable("skill", data.getSkill());
        context.setVariable("summary", data.getSummary());
        
        String html = templateEngine.process(template.getTemplatePath(), context);
        
        ByteArrayOutputStream out = new ByteArrayOutputStream();
        ITextRenderer renderer = new ITextRenderer();
        renderer.setDocumentFromString(html);
        renderer.layout();
        renderer.createPDF(out);
        
        return out.toByteArray();
    }
}
```

### 4.6 优缺点

**优点**：
- HTML/CSS 模板灵活，支持复杂排版和分页控制
- PDF 导出质量高，支持页眉页脚、分页等专业排版
- 模板维护方便，前端开发者也能参与编写
- 支持动态内容长度，自动适应排版
- Thymeleaf 与 Spring Boot 深度集成，配置简单

**缺点**：
- 需要引入新依赖（Thymeleaf、Flying Saucer）
- HTML 转 PDF 对 CSS 支持有限，部分样式可能丢失
- 学习成本较高，需要了解模板引擎和 PDF 转换工具
- Word 导出格式仍受限制（实际是 HTML 伪装成 .doc）

## 五、方案对比与推荐

### 5.1 方案对比表

| 对比维度 | 方案一（前端 CSS） | 方案二（poi-tl .docx） | 方案三（Thymeleaf/Freemarker） |
|----------|-------------------|----------------------|-------------------------------|
| **实现难度** | ⭐ 简单 | ⭐⭐ 适中 | ⭐⭐⭐ 较复杂 |
| **Word 导出质量** | ⭐ 一般 | ⭐⭐⭐ 优秀 | ⭐⭐ 良好 |
| **PDF 导出质量** | ⭐⭐ 一般 | ⭐⭐ 良好（需外部工具） | ⭐⭐⭐ 优秀 |
| **排版控制能力** | ⭐⭐ 有限 | ⭐⭐⭐ 较强 | ⭐⭐⭐ 强 |
| **新依赖引入** | 2 个前端库 | 1 个（poi-tl） | 2-3 个后端库 |
| **开发周期** | 短 | 中等 | 较长 |
| **模板维护** | 简单（CSS） | 中等（Word 文件） | 中等（HTML） |
| **课程设计适配** | ✅ 适合 | ✅ 适合 | ⚠️ 稍难 |
| **对应选型** | - | poi-tl | Thymeleaf/Freemarker |

### 5.2 推荐方案

**推荐方案二：后端 poi-tl 基于 .docx 模板文件**

**推荐理由**：
1. **符合课程设计水平**：难度适中，不需要过多新知识点
2. **对应指定技术选型**：sprint2.md 明确列出 poi-tl 作为候选方案
3. **已有技术基础**：项目已引入 Apache POI，poi-tl 基于 POI 开发，兼容性好
4. **导出质量保障**：Word 导出格式规范，保留模板样式，适合正式简历投递
5. **实现复杂度可控**：poi-tl 提供声明式模板语法（`{{name}}`），代码量少，易于理解和实现
6. **扩展性良好**：后续可扩展为更复杂的模板渲染

**不推荐方案一的原因**：
- PDF 质量不稳定，难以达到"符合正式投递标准"的要求
- Word 导出实际是 HTML 伪装，格式兼容性差
- 不属于 sprint2.md 指定的技术选型范围

**不推荐方案三的原因**：
- 需要学习新的模板引擎（Thymeleaf/Freemarker）和 PDF 转换工具（Flying Saucer），学习成本较高
- HTML 转 PDF 的 CSS 兼容性问题较难解决
- Word 导出格式仍受限制（实际是 HTML 伪装成 .doc）
- 超出课程设计的合理难度范围

### 6.7 PDF 导出方案

由于 poi-tl 仅支持 Word 生成，PDF 导出需要额外处理：

**方案 A（推荐）**：使用 LibreOffice 命令行转换（需服务器安装 LibreOffice）

```java
public byte[] exportPdf(Long templateId, ResumeData data) throws IOException, InterruptedException {
    byte[] wordBytes = renderWord(templateId, data);
    
    Path tempDocx = Files.createTempFile("resume", ".docx");
    Files.write(tempDocx, wordBytes);
    
    Path tempPdf = Files.createTempFile("resume", ".pdf");
    
    Process process = new ProcessBuilder(
            "libreoffice", "--headless", "--convert-to", "pdf",
            "--outdir", tempPdf.getParent().toString(),
            tempDocx.toString()
    ).start();
    
    process.waitFor();
    
    byte[] pdfBytes = Files.readAllBytes(tempPdf);
    
    Files.deleteIfExists(tempDocx);
    Files.deleteIfExists(tempPdf);
    
    return pdfBytes;
}
```

**方案 B**：使用 PDFBox 直接渲染文本（样式与 Word 模板不一致，作为降级方案）

### 6.8 智能推荐算法设计

根据 `sprint2.md` 要求，系统需根据用户工作年限、行业、目标岗位推荐适配模板。

**推荐规则**：

| 用户特征 | 推荐模板 |
|----------|----------|
| 工作年限 < 3年（应届生/初级） | 简约风格（simple） |
| 工作年限 3-5年（中级） | 专业风格（professional） |
| 工作年限 > 5年（高级/管理） | 专业风格（professional） |
| 目标岗位包含"设计"/"创意" | 创意风格（creative） |
| 目标岗位包含"学术"/"研究"/"博士" | 学术风格（academic） |
| 行业为"互联网"/"技术" | 简约/专业风格 |
| 行业为"金融"/"咨询" | 专业风格 |
| 行业为"教育"/"科研" | 学术风格 |

**实现思路**：

```java
@Service
public class TemplateService {
    
    public List<ResumeTemplate> recommend(Long userId) {
        User user = userMapper.selectById(userId);
        String industry = user.getIndustry();
        Integer workYears = user.getWorkYears();
        String targetJob = user.getTargetJob();
        
        List<String> recommendedCategories = new ArrayList<>();
        
        if (workYears != null) {
            if (workYears < 3) {
                recommendedCategories.add("简约");
            } else {
                recommendedCategories.add("专业");
            }
        }
        
        if (targetJob != null) {
            if (targetJob.contains("设计") || targetJob.contains("创意")) {
                recommendedCategories.add("创意");
            } else if (targetJob.contains("学术") || targetJob.contains("研究") || targetJob.contains("博士")) {
                recommendedCategories.add("学术");
            }
        }
        
        if (industry != null) {
            if (industry.contains("金融") || industry.contains("咨询")) {
                recommendedCategories.add("专业");
            } else if (industry.contains("教育") || industry.contains("科研")) {
                recommendedCategories.add("学术");
            }
        }
        
        if (recommendedCategories.isEmpty()) {
            recommendedCategories.add("简约");
        }
        
        QueryWrapper<ResumeTemplate> wrapper = new QueryWrapper<>();
        wrapper.in("category", recommendedCategories);
        wrapper.orderByDesc("created_at");
        
        return templateMapper.selectList(wrapper);
    }
}
```

## 九、总结

本方案文档提供了三种简历模板实现的技术路线：

1. **方案一**：前端 CSS + 浏览器导出，最简单但质量有限
2. **方案二**：后端 POI + .docx 模板，推荐方案，平衡难度与质量
3. **方案三**：后端 HTML + PDF 转换，功能最强但实现较复杂

**最终推荐方案二**，理由如下：
- 难度适中，符合大学生课程设计水平
- 基于项目已有依赖（Apache POI、PDFBox），学习成本低
- 导出质量高，满足正式简历投递需求
- 实现逻辑清晰，易于理解和维护
- 数据库设计严格遵循 sprint2.md 指定字段（id、name、category、preview_url、template_path、applicable_scene、created_at、updated_at）
