# AI 智能简历与求职助手 - 系统架构文档

## 1. 项目概述
本项目职通车是一款AI智能简历与求职助手，是一款面向求职者的Web应用。核心能力包含用户认证、简历导入与管理、AI智能分析（多维度评分+STAR法则修改建议）、简历模板化导出、个人目标岗位管理、简历-岗位匹配推荐、AI语音模拟面试、智能填写助手八大模块，通过大语言模型与匹配算法提升求职效率与简历质量。

项目采用前后端分离架构，基于 Vue3 + SpringBoot3 技术栈构建，支持容器化部署。

## 2. 技术栈选型

## 3. 整体架构设计
项目采用经典三层前后端分离架构，自上而下分为：
1. **表现层**：前端 Web 页面，负责用户交互与数据展示
2. **服务层**：后端业务服务，处理核心逻辑与 AI 能力对接
3. **数据层**：数据库，存储用户、简历、分析记录等业务数据

同时数据层独立出AI能力适配层，统一封装第三方大模型调用，实现模型可插拔切换。

### 4.3 核心算法与机制（AI 禁飞区 - 自研逻辑）

**已实现算法（Sprint 1）：**
1. **简历多维度权重评分**：从个人总结（10%）、教育背景（15%）、工作经历（25%）、技能（25%）、项目经验（25%）5个维度设置权重，量化计算简历得分（0-100分），权重存储于数据库便于动态调整
2. **STAR法则修改建议生成**：基于STAR法则（情境-任务-行动-结果）分析简历各分段内容，识别描述缺陷并生成结构化修改建议，引导用户量化经历描述


**规划中算法（Sprint 2）：**
3. **岗位相似度匹配排序**：基于文本特征与关键词匹配度，提取简历核心特征（教育、技能、项目、工作经历关键词）与岗位文本特征（JD关键词、任职要求），计算多维度匹配度（技能匹配度、经验匹配度、学历匹配度、整体契合度），支持匹配结果排序与AI推荐理由生成


**规划中算法（Sprint 3）：**
4. **模拟面试对话状态机**：维护面试流程状态（开场-提问-追问-总结），控制多轮对话的上下文与节奏，支持正常/压力两种模式切换，面试结束后生成复盘报告与能力图谱


## 5. 核心业务流程

**已实现流程（Sprint 1）：**

### 5.1 用户注册登录流程
用户输入邮箱 → 发送验证码（邮箱）→ 验证验证码 → 注册成功 → 登录生成JWT Access Token + Refresh Token → Token过期自动刷新 → 忘记密码/重置密码

### 5.2 简历导入流程
用户上传Word/PDF/JPG文件（大文件分片上传）→ 后端解析文件（PDFBox/POI提取文本，OCR识别图片）→ 提取文本内容 → 结构化简历数据 → 返回前端编辑

### 5.3 AI智能分析流程
用户点击"AI智能分析" → 后端组装分析 Prompt → 调用大模型 API（阿里云 Qwen/DashScope）→ 解析5维度评分结果（个人总结、教育背景、工作经历、技能、项目经验）→ 基于STAR法则生成修改建议 → 返回前端雷达图展示评分与改进建议 → 分析记录持久化


**规划中流程（Sprint 2）：**

### 5.4 个人目标岗位管理流程
用户手动添加目标岗位 → 填写岗位名称、公司、薪资范围、工作地点、JD描述、任职要求 → 保存到目标岗位列表 → 支持编辑/删除已保存岗位

### 5.5 AI联网搜索补全流程
用户输入岗位关键词 → 调用大模型联网搜索 → 自动补全岗位JD描述与任职要求 → 用户手动修正 → 保存到目标岗位列表

### 5.6 简历-岗位匹配推荐流程
用户选择简历与目标岗位 → 提取简历核心特征（教育、技能、项目、工作经历关键词）→ 提取岗位文本特征（JD关键词、任职要求）→ 计算多维度匹配度（技能匹配度、经验匹配度、学历匹配度、整体契合度）→ 生成AI推荐理由（匹配亮点与差距项）→ 返回匹配结果排序与历史记录

### 5.7 简历模板化导出流程
用户进入模板广场 → 系统根据用户工作年限、行业、目标岗位智能推荐适配模板 → 用户选择模板 → 自动填充个人信息与简历分段内容 → 选择导出格式（Word/PDF）→ 后端渲染模板 → 生成文件 → 返回文件流 → 前端下载


**规划中流程（Sprint 3）：**

### 5.8 AI语音模拟面试流程
用户选择面试模式（正常/压力）→ 初始化对话状态机 → 大模型生成首道面试题（流式输出优化性能）→ 用户文字/语音作答 → 模型追问/点评 → 循环直至面试结束 → 生成面试复盘报告与能力图谱（呈现现有能力与目标岗位要求的差距）

### 5.9 智能填写助手流程
用户输入口语化经历描述 → 后端生成优化 Prompt → 调用大模型生成专业简历语句 → 返回结果 → 用户多轮迭代修改 → 采纳/复制到简历

## 6. 数据架构

### 已实现数据表

**核心业务表：**
- **users**：存储账号、密码哈希、基础信息（姓名、手机号、出生日期、学历、工作年限、城市）、账号状态、登录时间
- **resumes**：简历基础信息、关联用户、标题、版本号、来源类型（MANUAL/IMPORT）
- **resume_details**：分段存储教育经历、工作经历、项目经验、技能、个人总结等，支持 CONTENT 类型为 MEDIUMTEXT
- **resume_files**：上传文件信息、文件类型、存储路径、文件大小、MD5（秒传）、OCR识别结果、解析状态

**分析记录表：**
- **analysis_records**：简历分析记录，存储5维度评分（个人总结、教育背景、工作经历、技能、项目经验）、权重配置、综合总分、AI优化建议、分析状态

### 规划中数据表（Sprint 2）
- **目标岗位表（target_jobs）**：用户个人目标岗位数据、岗位名称、公司、JD描述、任职要求、薪资范围、工作地点、来源（MANUAL/AI_SEARCH）
- **匹配记录表（match_records）**：简历-岗位匹配记录、匹配度得分、多维度匹配度（技能/经验/学历/整体契合度）、AI推荐理由
- **模板信息表（resume_templates）**：模板分类、模板名称、预览URL、模板路径、适用场景

### 规划中数据表（Sprint 3）
- **面试会话表**：面试记录、对话历史、状态快照、面试模式（正常/压力）、复盘报告、能力图谱
- **智能填写对话表**：智能填写助手对话记录、用户输入、AI生成内容、采纳状态

### 数据迁移工具
采用 Flyway 进行数据库版本管理，迁移脚本位于 `db/migration/` 目录：
- V1：初始化核心表（users、resumes、resume_details、resume_files）
- V2：新增分析记录表（analysis_records）
- V4：兼容旧库增量升级，新增 source_type、file_md5 字段
- V5：统一存储模型，扩展字段并迁移数据

## 7. 部署架构
采用 Docker 容器化部署方案：
1. 前端项目打包为静态资源，构建 Nginx 镜像提供 Web 服务
2. 后端 SpringBoot 项目构建为 Jar 包镜像，独立容器运行
3. 数据库可采用容器部署或独立云数据库
4. 外层 Nginx 统一入口，负责静态资源分发与后端接口反向代理
